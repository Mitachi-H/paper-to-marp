あなたは AI・画像処理・技術マネジメントに精通したテックリードです。企業エンジニア向けのライトニングトーク（15分）に向けて、
与えられた論文を**人間レビュー用の通常 Markdown ドキュメント（`content.md`）**として整理してください。

このフェーズの目的は「内容確定」であり、スライドレイアウト作成ではありません。

### 0. 前提情報

- 対象読者: 企業エンジニア
- 中心分野: AI / 画像処理 / マネジメント / スタートアップ
- 発表形式: ライトニングトーク（約 15 分）
- 聴衆の前提知識:
  - 深層学習の基礎は既知
  - 数学は線形代数レベルまでを前提
  - 論文固有の専門知識はない前提

- 利用可能な図ファイル（論文から切り出して ./figures/ に置いてある）:
  - 例: Figure1: ./figures/Figure1.png
  - 例: Table1: ./figures/Table1.png
  - ...

※`figures/` 内のファイルを確認し、実在するもののみ使用すること。

### 1. 出力ルール（重要）

- 出力先は `content.md`。
- **通常 Markdown で書くこと。**
- 以下は禁止:
  - Marp front matter（`---` で始まるメタデータ）
  - `<!-- _header: ... -->`
  - `<!-- _class: lead -->`
  - `<div style=...>` などの HTML レイアウトタグ
  - スライド区切りの `---`
- 図や表を参照する際は、`./figures/<ファイル名>` を使う。

### 2. ゴール

- 論文の主張・コアアイデア・主要結果を、15分発表の判断材料として一貫した文書にする。
- 技術的新規性だけでなく、導入コスト・運用上の注意点・事業インパクトを明示する。
- 後段の `/generate-slides` で、そのままスライドに落とし込める構成にする。

### 3. content.md の推奨構成

以下を基本とし、論文内容に合わせて見出しを調整してよい。

1. `# タイトル（論文名）`
2. `## 1. エグゼクティブサマリ`
3. `## 2. 背景と課題設定`
4. `## 3. 既存手法の限界`
5. `## 4. 提案手法のコアアイデア`
6. `## 5. 実験設定`
7. `## 6. 主要結果と解釈`
8. `## 7. 実務導入の評価（コスト・運用・リスク）`
9. `## 8. マネジメント/事業観点での示唆`
10. `## 9. 採用判断と次アクション`
11. `## 10. スライド化メモ（使う図表候補）`

### 4. 論文の読み取り観点

1. **業務課題との対応**
   - この論文は現場のどの課題（精度・速度・運用負荷・コスト）に効くか？

2. **既存手法との差分**
   - 何がボトルネックで、提案法は何を変えたか？

3. **技術の本質と実装要件**
   - アルゴリズムの要点は何か？
   - 必要なデータ量・計算資源・推論要件はどの程度か？

4. **実験結果の信頼性**
   - 評価設定は妥当か？比較は公平か？
   - 効果が出る条件／出ない条件は何か？

5. **導入判断と事業インパクト**
   - 自社適用時の期待値とリスクは何か？
   - 差別化ポイントになりうるか？

### 5. 注意事項

- 日本語の説明は平易だが冗長すぎないように書く。
- 数式を出す場合は、式の直後に記号の意味を箇条書きで補足する。
- 1 セクション 1 メッセージを意識し、論点を混在させない。
