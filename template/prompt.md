### 1. ゴール

- 対象: 東京大学の理系大学院生（主専攻: AI / Machine Learning / Neuroscience）
- 目的: 上記の論文を 60–90 分程度で輪読できるようにする「深堀りスライド」を作成する。

### 2. 出力

- 出力は **Marp 用 markdown ファイル** とする。

---

- 以降は，スライド定義のみを書く。
- コードブロックやシェル記法では包まない（` ``` ` は使わない）。そのまま `slide.md` として保存して使える形にする。

### 3. スライド全体構成

おおよそ 20–30 枚を目安に，以下のような構成にしてください（論文内容に応じて調整可）:

1. **タイトルスライド**（lead）
2. **目次スライド**
3. **問題設定・モチベーション（背景）**
4. **既存手法 / 関連研究**
5. **基本的な数理定式化（モデルやタスクの数式による記述）**
6. **提案手法のコアアイデア（概念図 + 直観的説明）**
7. **提案手法の数理的定義 / アルゴリズム**
8. **学習手法・カリキュラム / 損失関数**
9. **理論解析・性質（あれば）**
10. **実験設定（データセット・ベースライン・指標）**
11. **主な結果 (メインテーブル・図)**
12. **アブレーション / 解析 (例: パラメータやハイパーパラメータの影響)**
13. **定性的分析・ケーススタディ**
14. **議論: 何が新しいか？どのような状況で効くか？限界は？**
15. **まとめ & 今後の課題**

### 4. 各スライドの書式ルール

1. **タイトルスライド**

```markdown
<!-- _class: lead -->

# {{SeminarName}} 深堀り資料

{{PaperTitle}}

<br>

**{{PresenterName}}**  
{{Affiliation}}  
{{Date}}
```

2. **通常スライド**

- 先頭行にヘッダを付ける:

```markdown
<!-- _header: 背景：〜〜〜 -->
```

**「そのスライドの主張（メッセージ）」**を書く。単なる名詞止めは避け、文として成立させる。

- 例: `<!-- _header: 目的：離散トークン制約を排除し、思考の探索空間を拡張する -->`

- スライド内の見出しは `####` で書く:

```markdown
#### 前提：...
```

スライドの主張をサポートするような内容。スライドの主張を繰り返すわけではない。

- 箇条書きを基本にし，1 スライドのテキスト量を詰め込みすぎない。

3. **セクション区切りスライド**

- セクションの切り替え時は `<!-- _class: lead -->` を使い，大きめのタイトルだけにする:

```markdown
<!-- _class: lead -->

## {{セクション名}}

<small>{{必要なら英語サブタイトル}}</small>
```

### 5. 図・表の使い方

- 論文の重要な図・表は，なるべくスライドに取り入れる。
- 図を挿入するときは，あらかじめ与えたファイル名を使って以下のように書く:

```markdown
![w:1100 center](./figures/Figure1.png)
```

- 図の上または下に，**図の要点を 2–4 行の箇条書きで日本語で説明**する。
- 表も画像として貼る場合は同様:

```markdown
![w:900 center](./figures/Table1.png)
```

- 図の近くで，元論文の Figure / Table 番号を明記する（例: 「_Figure 3 より_」）

### 6. 数式・記号の扱い（重要）

- 数式は KaTeX 形式で書く。

  - インライン: `$H_t \in \mathbb{R}^{t \times d}$`
  - ブロック:

```markdown
$$
H_t = \mathrm{Transformer}(E_t), \qquad
M(x_{t+1} \mid x_{\le t}) = \mathrm{softmax}(W h_t)
$$
```

- 各ブロック数式の直後には，**必ず記号と次元を説明する箇条書き**を入れる:

```markdown
- $E_t = [e(x_1), \dots, e(x_t)] \in \mathbb{R}^{t \times d}$：位置 $t$ までのトークン埋め込み
- $H_t \in \mathbb{R}^{t \times d}$：最終層の隠れ状態の列
- $h_t = H_t[t, :] \in \mathbb{R}^{d}$：時刻 $t$ の隠れ状態
- $W \in \mathbb{R}^{V \times d}$：語彙サイズ $V$ の出力線形層
```

- 論文に特有の記号（例: 連続思考ベクトル，ポリシー，エネルギー関数など）があれば，

  - 専用スライドを 1 枚用意して**すべて列挙して定義**すること。

- 変分推論・RL などで勾配が複雑な場合，

  - 「何に対して勾配を取り，どの項が微分可能/非微分か」を文章＋式で丁寧に説明する。

### 7. 内容の深さと説明スタイル

- 聴衆は

  - Transformer / LLM / 逆伝播 / 事前学習 といった基本概念は知っている前提。
  - しかし，この論文固有の発想やトリックは知らない前提。

- したがって，

  - **直観的な説明**と**数理的に厳密な説明**を両方入れる。
  - 可能なら，脳神経科学との類比・関連（MD ネットワーク，潜在表現など）も 1–2 スライドでコメントする。

### 8. 論文全体の読み取り方

スライドを作る前に，論文を以下の観点で解析すること:

1. **問題設定**

   - どのタスク / 評価指標について，どんな限界があると主張しているか？

2. **既存手法の限界**

   - 著者が特に批判しているポイント（計算効率，表現力，faithfulness など）は何か？

3. **提案手法の本質**

   - 「どのモジュールを置き換えたのか」「既存アーキテクチャとの違い」を数式レベルで説明できるようにする。

4. **実験からの take-home message**

   - どのタスクでどれくらい改善し，どのタスクではそうでもないのか。
   - 効いている要素がどれか（カリキュラム，潜在トークンの数，モデルサイズなど）。

5. **今後の展望**

   - この手法を AI / neuroscience の文脈でどう発展させうるかを 1 スライドで議論する。

### 9. 注意事項

- 日本語の説明は平易だが冗長すぎないように書く。
- 1 スライド中の数式ブロックは多くても 1〜2 個までにする。
- コードブロックにはプログラムではなく疑似コードを載せる場合のみ用いる（必要なら）。
